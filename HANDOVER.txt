INITIAL IMPORT DESIGN
The importer matches exact filenames and Minecraft/loader metadata; it never
silently substitutes a newer mod release. It saves successful records as it
goes. Exact Modrinth version IDs, version-number lookups, and hash lookups
are supported. CurseForge API access needs CURSEFORGE_API_KEY when used;
never put a key into the repository. All current records are already resolved.
The importer is for initial creation only: it refuses an existing pack.toml
or a nonempty mods directory. Once built, use packwiz for maintenance.

CLIENT UPDATER BEHAVIOR
Place sync-mods.cmd in the game's instance folder beside mods/. Close the
running game first. It requires Windows x64, downloads portable Java 21 for
its own use, and runs the packwiz installer with client-side selection and an
explicit instance directory. It uses a lock and a local .packwiz-sync cache,
and refuses to run from the pack source repository.
Keep packwiz.json: the installer uses it to track managed files.
The script does not install Minecraft or NeoForge, change the launcher's Java
setting, or wipe old manually installed mods. Different old filenames may
remain, which is why the first sync should use a clean instance.
The publishing workflow supplies the correct URL in the distributed script;
the source copy retains its placeholder until a host is configured.
